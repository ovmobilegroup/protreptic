## 1. 方法与口径

### 1.1 逐件五步核验（20/20 全覆盖）

1. 载荷形态与条数核实：枚举该件全部相关文件（data/figures/、data/individuals/、docs/figures/），逐文件实测载荷容器名、条数、id 列表与 id 风格（legacy M 加三位数 / v6 M-代号-三位数），并区分主文件、伴随包（_modes.json）与镜像三类。
2. 身份核验：查 data/figure_names.json（代号到姓名）、data/code_maps.json、库内同名与同码条目、docs/ 全库检索、git 全历史；对重点存疑件另做公开资料交叉检索（外部来源只用于判是否真实，不进档案内容）。查不到一律写「未能核实」，不臆造身份。
3. 内容质量抽查：每件抽取载荷样本（模式名、定义、引文、出处、案例）与字段填充率（引文、出处、案例填充条数，定义平均字数），标记空引文、空出处、出处不可落源、引文归属错误、事实硬伤、模板化流水线痕迹。
4. 库内重叠核查：同码（库内 figure_code 计数）、同名（库内 figure_name 精确与子串检索）、旧编号全局唯一性（把 20 件全部 legacy id 放到全库文件范围做占用统计，见第 7 节风险 1）。本卡对 H-DY-001 冲突只读注明状态（处理卡 t_72e34e75），不裁决。
5. 结论与预分配：结论三值（可行 / 存疑 / 不可）；工作量按复刻一件的完整动作量估算（id 重编、related_modes 重指、category 归一、三处一致、引文落源抽核、门禁、两仓 parity）；figure_code 与模式前缀一律进全库码集查重后给唯一方案。
