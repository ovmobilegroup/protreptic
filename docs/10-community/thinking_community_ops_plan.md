## 一、社区架构

### 1.1 社区定位

**我们要做什么：**

| 维度 | 内容 |
|------|------|
| **使命** | 构建全球最大的中文思维模式开源知识库，让每个人都能拥有顶级决策能力 |
| **愿景** | 让思维模式从"少数人的秘密武器"变成"每个人的日常工具" |
| **核心价值** | 开放共享、实战验证、持续迭代、多元包容 |

**我们不做什么：**

- ❌ 不做纯学术讨论——一切以实战验证为准
- ❌ 不做人身攻击——对事不对人，争议围绕内容本身
- ❌ 不做无意义灌水——每条贡献必须有实质内容
- ❌ 不做封闭付费墙——核心知识库永远免费开源

### 1.2 社区角色体系

社区采用**四级角色体系**，逐级晋升，每级对应不同的权限和责任。

#### Level 1：观察者（Observer）

| 属性 | 说明 |
|------|------|
| **获取方式** | 注册即自动获得 |
| **权限** | 浏览全部知识库、阅读案例、参与讨论 |
| **责任** | 遵守社区规则 |
| **积分要求** | 0 分 |
| **标识** | 👁️ 观察者 |

#### Level 2：贡献者（Contributor）

| 属性 | 说明 |
|------|------|
| **获取方式** | 累计 50 积分，或通过 3 个有效贡献审核 |
| **权限** | 提交新案例/新模式、发起 PR、评论他人贡献、投票 |
| **责任** | 遵守投稿规范、保证贡献质量 |
| **积分要求** | 50 分 |
| **标识** | ✍️ 贡献者 |

#### Level 3：审核者（Reviewer）

| 属性 | 说明 |
|------|------|
| **获取方式** | 累计 200 积分 + 社区提名 + 连续活跃 3 个月 |
| **权限** | 审核他人 PR、标记采纳/驳回、编辑社区文档、发起季度评审 |
| **责任** | 公正审核、维护内容质量标准、帮助新人 |
| **积分要求** | 200 分 |
| **标识** | 🔍 审核者 |
| **上限** | 社区总人数 5% |

#### Level 4：管理员（Admin）

| 属性 | 说明 |
|------|------|
| **获取方式** | 创始人任命 或 社区公投选举（需 75% 支持率） |
| **权限** | 全部权限 + 角色升降级 + 社区规则修改 + 争议终审 |
| **责任** | 社区方向把控、重大决策、危机处理 |
| **标识** | 🛡️ 管理员 |
| **上限** | 3 人 |

### 1.3 社区规则

#### 投稿规范

所有贡献必须遵循以下格式：

```markdown
## 贡献类型：{新模式 / 新案例 / 错误修正 / 写作技法 / 结构框架}

### 标题
{简洁有力的标题}

### 一句话定义
{用一句话概括核心}

### 正文
{详细内容，遵循知识库现有格式}

### 来源/依据
{出处：书籍/文章/个人实战经验/研究论文}

### 验证状态
{□ 未验证 □ 个人验证 ✓ □ 社区验证 ✓✓}

### 关联模式
{与知识库中哪些已有模式相关}
```

#### 审核标准

| 维度 | 合格标准 | 权重 |
|------|---------|------|
| **原创性** | 不是简单复制，有自己的理解或补充 | 30% |
| **实用性** | 有明确的操作步骤和适用场景 | 30% |
| **准确性** | 概念定义清晰，逻辑自洽 | 20% |
| **格式规范** | 遵循投稿模板 | 10% |
| **社区价值** | 能填补知识库空白或显著提升现有内容 | 10% |

**综合评分 ≥ 70 分** 为采纳，**50-69 分** 为修改后复审，**< 50 分** 为驳回。

#### 争议处理机制

```
争议发生 → 提交争议说明 → 审核者初审 → 
  ├─ 达成一致 → 按共识修改 → 结案
  ├─ 无法一致 → 提交社区投票（审核者以上角色参与）
  │   ├─ 多数同意 → 按投票结果执行
  │   └─ 仍无法一致 → 管理员终审
  └─ 恶意攻击 → 警告 → 第二次违规 → 暂停贡献权限 → 第三次 → 永久封禁
```

## 二、贡献流程

### 2.1 总体流程概览

```
┌─────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  发现/创作   │ →  │  提交 PR     │ →  │  社区审核    │ →  │  合并入库    │
│  新思路/案例 │    │  (Draft)     │    │  (Review)    │    │  (Merge)     │
└─────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
                        ↑                        ↓
                    快速修复                  版本发布
                   (hotfix)                (release)
```

### 2.2 三种贡献通道

#### 通道 A：新案例提交（最快，≤ 5 分钟）

适用于：你在实际工作中验证了一个思维模式的效果。

```
步骤 1: 一键提交
  在 Hermes 会话中发送：
  /contribute case
  场景：{什么问题}
  模式：{#编号 + 名称}
  结果：{达成了什么}
  教训：{学到了什么}
  评分：⭐⭐⭐⭐⭐

步骤 2: 自动归档
  → 存入 本体系/extras/cases/pending/
  → 通知审核者待审

步骤 3: 审核合并
  → 审核者 48 小时内审核
  → 合格 → 移入 cases/ 正式目录
  → 不合格 → 退回并说明理由

步骤 4: 自动奖励
  → 贡献者 +10 积分
  → 审核者 +5 积分（审核劳动）
```

#### 通道 B：新思维模式提议（严谨，1-2 周）

适用于：你从书中、研究中提炼出一个全新的思维模式。

```
步骤 1: 创建提案 PR
  在 pending/ 目录下创建 {模式名称}.md
  按照知识库 source/ 文件的格式规范编写

步骤 2: 社区预审（3 天）
  → 至少 3 名贡献者评论
  → 审核者给出初步评分

步骤 3: 专家评审（7 天）
  → 审核者及以上角色组成评审组
  → 按审核标准打分
  → 投票决定采纳/修改/驳回

步骤 4: 公示期（3 天）
  → 采纳的模式进入"候选库"
  → 社区可继续提意见
  → 公示期满无异议 → 正式纳入知识库

步骤 5: 版本更新
  → 更新 quick_reference.md
  → 更新相关技能包
  → 发布版本摘要
```

#### 通道 C：错误修正（快速，≤ 10 分钟）

适用于：发现错别字、概念错误、过时内容。

```
步骤 1: 标记问题
  在对应文件下创建 issue 或直接提交 PR

步骤 2: 快速审核
  → 审核者 24 小时内确认
  → 简单修正（错别字/格式）→ 直接合并
  → 内容修正 → 需 2 名审核者确认

步骤 3: 补丁版本
  → 修正合并后打 patch 版本号
  → 记录在 releases/ 中
```

### 2.3 PR 模板

```markdown
## Pull Request

### 贡献类型
{案例 / 新模式 / 修正 / 其他}

### 标题
{简洁描述}

### 变更内容
{详细说明改了什么、新增了什么}

### 关联 Issue
{如有}

### 自测清单
- [ ] 格式符合规范
- [ ] 内容经过验证
- [ ] 无抄袭/搬运
- [ ] 已检查与现有内容的关联性

### 截图/证据（可选）
{如果有实战截图或数据来源，附上}
```

## 四、运营节奏

| 时间 | 活动 | 负责人 | 耗时 |
|------|------|--------|------|
| 早 9:00 | 审核昨日 PR（新案例/修正） | 值班审核者 | 30 min |

| 随时 | 快速修正审核（24h 内） | 值班审核者 | 10 min/条 |

## 七、风险与应对

### 风险矩阵

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| **内容质量参差不齐** | 高 | 高 | 严格审核标准 + 模板约束 + 审核者培训 |
| **社区活跃度下降** | 中 | 高 | 持续的活动节奏 + 积分激励 + 新鲜感维持 |
| **核心贡献者流失** | 中 | 高 | 多元化角色体系 + 认可机制 + 情感连接 |
| **恶意破坏/灌水** | 低 | 高 | 审核门槛 + 举报机制 + 封禁制度 |
| **知识产权争议** | 低 | 中 | 明确 CC BY-SA 4.0 协议 + 来源标注要求 |
| **运营者精力不足** | 高 | 中 | 自动化优先 + 审核者分担 + SOP 文档化 |
| **社区分裂/内斗** | 低 | 极高 | 争议处理机制 + 管理员仲裁 + 文化引导 |

### 核心运营原则

1. **自动化优先**：能自动化的绝不人工，减少运营负担
2. **低门槛进入，高标准产出**：任何人都可以提交，但审核不放松
3. **正向循环**：贡献 → 认可 → 更多贡献
4. **透明运作**：所有规则、流程、数据公开可见
5. **渐进式扩张**：先小范围验证，再逐步放开
